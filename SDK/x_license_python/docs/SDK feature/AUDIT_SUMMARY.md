## Findings and Resolution

### Resolved locally: Example license-key output

The prior version of `SDK/x_license_python/example_app.py` printed `client.get_current_key()` on every loop iteration, exposing the credential in captured stdout. The current sample prints progress without the key. `test_example_app_security.py` exercises the CLI with a sentinel key and asserts it is absent from output. This is locally source/test verified; it is not hosted or production verification.

### Low: Public-IP fallback is mislabeled

`DeviceManager.get_public_ip()` stores `get_local_ip()` as its fallback when the external lookup fails, then returns it under the `public_ip` telemetry key. This can misreport a private LAN address as a public IP. The lookup is explicitly opt-in and validation does not request it; the implementation is unchanged here.

### Resolved locally: Package README example syntax

The prior `res.request_id` snippet had inconsistent indentation. The current snippet uses a string/nonblank guard and consistent Python block indentation. `test_readme_quick_start.py` now parses all fenced Python examples in the package README in addition to checking the repository-root quick start.

### Informational: Screenshot error is stale relative to this checkout

The screenshot requires `app_version` as a config field. Current `test/app.py` requires `server_url`, `app_name`, and `public_key_pem`; when `app_version` is absent, GUI and CLI ask for the actual client release version and do not use `min_version`. The focused regression suite passed 46/46. If the screenshot still appears, verify that the console is launched from the updated SDK checkout rather than an older extracted copy.

## Security Properties Verified in Source and Tests

- Remote SDK URLs require HTTPS; HTTP is limited to localhost/loopback during development.
- Authorization and heartbeat responses require a configured trusted PEM public key and cryptographic verification; missing `cryptography` fails closed.
- Heartbeats bind a fresh nonce, and explicit denial, malformed data, signature/challenge errors, and TLS errors are not granted transient outage grace.
- License-key persistence is disabled; legacy temp-file sessions are rejected/cleared. Auto-login consequently has no saved key to reuse.
- Diagnostic live targets require exact operator allowlists; Production has a separate allowlist and separate consent gates. An allowlist is not proof of environment.
- Diagnostic reports redact active keys and identifying host/device values. Diagnostics can still create server-side records and bind/unbind the disposable license.
